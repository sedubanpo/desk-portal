# 사무실 연속 드래그 시간 초과 조사

## 확인된 원인

1. **검사 좌표 오류**: 원래 검사는 출발 캐릭터만 `scrollIntoViewIfNeeded()`로 스크롤했다. 세 번째 이동(본관 2번 → 강의실)에서 도착 명패의 위치는 y=919, 높이=42로, 화면 높이 900 밖이었다. 마우스를 놓는 중심점은 y=940이었다. 그 이동에 대한 `saveDeskOffice` HTTP 요청은 없었다. 서버의 자리 교환 실패가 아니라 유효한 도착 지점 밖으로 드롭한 검사 오류다.
2. **동일 데이터의 DOM 교체**: `docs/mini-office.js`의 `connect()`는 모든 SSE 스냅샷에서 `paint()`를 호출했다. `paint()`는 `.mo-scene.innerHTML`을 교체하므로 동일 데이터 재전송에서도 검사 대상 요소가 분리되고 실제 사용자의 키보드 포커스도 사라졌다. 기존 스크립트의 `Element is not attached to the DOM`과 연결된다.
3. **검사 동기화 부족**: 기존 검사는 상대 화면의 배치만 확인한 후 다음 드래그를 시작했다. 이제 이동 요청 발생·응답과 조작 중인 화면의 새 배치도 확인한다.

## 수정

- 서버 시각(`serverTime`)을 제외한 스냅샷이 동일하면 자리 DOM을 보존한다. 연결 상태와 서버 시각 보정은 계속 갱신한다. 날짜·계정이 바뀌면 비교값도 초기화한다.
- 드래그 검사는 출발/도착 영역이 모두 화면 안에 들어오도록 스크롤하고 두 영역의 가시 좌표를 명시적으로 검사한다.
- 이동 요청 전송·종료 및 양쪽 화면의 배치 반영을 기다린다. 단순히 제한 시간을 늘리지 않았다.
- 같은 데이터 재전송 시 캐릭터 버튼과 키보드 포커스가 유지되는 회귀 검사를 추가했다.

## 검증 범위

운영 데이터는 읽거나 변경하지 않았다. 로컬 Express API, 메모리 저장소, 합성 계정 두 개와 실제 Chrome 포인터 조작으로 검사했다.

- 수정 전 JS에 새 포커스 유지 검사를 적용: `false !== true`로 실패하여 문제 재현.
- 수정 후: 동일 스냅샷 포커스 유지, 빈자리 이동, 다른 직원과 교환, 강의실 복귀, 두 화면 동기화 검사.
- 기존 시나리오: 업무 시작/수정/완료, 일지 원자적 기록, 진행률, 권한, 퇴근·연장 근무, 모바일, 오프라인 복구, 재연결, 구독 해제.
- 전체 브라우저 시나리오를 3회 연속 실행하여 모두 통과했다(빈자리 이동·교환·복귀 총 9회).
- 서버 단위 테스트 415개 통과.

실행: 저장소 루트에서 `PLAYWRIGHT_MODULE=<Playwright 설치 경로> node services/desk-api/scripts/test-office-browser.mjs` 및 `node --test services/desk-api/test/*.test.js`.

## 배포

사용자의 후속 배포 요청에 따라 GitHub Pages 운영 반영을 진행한다. 사무실 JS의 캐시 버전을 갱신하여 새 페이지 로드에서 수정본을 받도록 했다. 서버 코드 및 운영 설정 변경은 없다.

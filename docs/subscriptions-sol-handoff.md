# sol 세션 전달문: 유료 구독 금액 연동

데스크 포털의 **물품 관리 → 유료 구독 현황**에 실제 계정 기준 월별 요금을 연동해 주세요. 구독 관리 UI·월별 입력·로고·보고 이미지 복사는 구현되어 있습니다. 기본 화면은 소모품 현황이며 구독은 별도 소메뉴입니다.

## 대상과 원칙

- Google Workspace (`google`), ChatGPT (`chatgpt`), Firebase (`firebase`), Supabase (`supabase`), Notion (`notion`): 먼저 공식 문서와 실제 계정의 청구 데이터 접근 가능성을 조사한 뒤 가능한 항목부터 연동합니다.
- **배민클럽 (`baemin`)은 사용자가 직접 입력합니다. 자동 조회·덮어쓰기 대상에서 제외하세요.** 직접 추가한 구독도 기본값은 수동입니다.
- 공개 요금표만 보고 실제 청구액으로 입력하지 마세요. 계정의 플랜·좌석 수·사용량·청구 주기·통화·세금·할인에 따라 달라집니다.
- ChatGPT 구독료와 OpenAI API 사용료를 혼동하지 마세요. Firebase 프로젝트 비용과 Google Cloud 청구 합계가 중복 집계되지 않도록 범위를 정하세요.
- 공식 API/청구 내보내기/인보이스 등 지원되는 경로를 우선합니다. 자동 조회가 불가능하거나 권한이 없다면 수동 입력을 유지하고 이유를 표시합니다. 청구 화면 스크래핑이나 비공개 API를 전제로 구현하지 마세요.
- 미청구 사용량 추정과 확정 청구액, 결제 완료 여부를 분리하세요. 추정값을 결제 완료로 표시하지 마세요. 조회 실패·권한 없음·미입력은 0원과 다릅니다.

## 구현 위치

저장소: `/Users/anjongseong/Documents/desk-portal`
- `docs/subscriptions.js`: 기본 서비스, 월별 목록, 입력/설정, 합계, PNG 생성·복사
- `docs/subscriptions.css`: 구독 화면 및 소메뉴 아이콘 스타일
- `docs/index.html`: 물품 관리 소메뉴와 패널, 구독 로딩 연결
- `services/desk-api/src/desk/handlers.js`: 설정 경로 허용, 구독 데이터 검증·동시 수정 보호
- `docs/subscriptions-maintenance.md`: 현재 데이터 모델 상세

현재 API는 인증된 `getDeskPortalConfig` / `saveDeskPortalConfig`입니다.
- scope: `daily`
- 전체 조회 key: `subscriptions`
- 항목별 저장 key: `subscriptions/<serviceId>`
- `expectedValue`에 직전 조회값을 보내며 충돌 시 최신값을 다시 읽어 해당 월 변경만 병합해야 합니다. 원장 전체 덮어쓰기는 금지되어 있습니다.

```js
{
  id, name, plan, active, logo, asset, description,
  payments: {
    'YYYY-MM': {
      date: 'YYYY-MM-DD', // 미입력은 빈 문자열; 현재는 해당 월의 날짜만 허용
      amount: null,      // 미입력; 0은 실제 0원
      currency: 'KRW',   // KRW 또는 USD
      status: 'unknown', // unknown / scheduled / paid
      note: '',
      updatedAt, updatedBy // 변경 월에 서버가 기록
    }
  }
}
```

현재는 구독별 월 1개 합산 기록이며 합계는 예정 금액도 포함하고 통화를 섞지 않습니다. 여러 인보이스, 결제월과 사용월 차이, 크레딧/환불을 지원하려면 모델과 서버 검증, 화면·보고서·테스트를 함께 확장하세요. 현재 음수 금액은 거부됩니다.

## 연동 시 필요한 작업

1. 서비스별 조회 가능 여부, 필요한 권한, 공식 근거, 데이터 범위와 갱신 주기를 정리하세요. 공개 정가와 실제 계정 청구액을 구분하세요.
2. 서비스별 `수동 / 연동` 설정을 두고 기본은 수동으로 유지하세요. 필요한 인증 정보는 서버의 기존 비밀 관리 방식으로 보관하고 프런트엔드·Git·로그에 넣지 마세요.
3. 출처, 조회 시각, 대상 청구 기간, 확정/예상 여부, 연동 오류를 별도 메타데이터로 보존하고 화면과 보고서에도 명확히 표시하세요. 현재 사용자 비고를 메타데이터 저장 공간으로 덮어쓰지 마세요.
4. 자동 연동은 다른 월 기록, 사용자 비고·로고·구독명, 수동 수정 금액을 보존해야 합니다. 수동 우선 정책과 덮어쓰기 여부를 명시하고 실패 시 마지막 성공값을 유지하세요.
5. 배민클럽 제외, 중복 청구 방지, 통화 구분, 재실행 시 중복 없음, 부분 실패, 월 경계, 동시 수정 충돌을 테스트하세요. 운영 계정에 테스트 청구·구독 구매·요금제 변경을 하지 마세요.
6. 실제 요금 연동이 적용된 서비스만 연동 완료로 안내하고, 나머지는 수동/연동 불가/권한 필요를 구분하세요.

이 전달문은 준비만 된 상태이며 sol 세션에 자동 전송하지 않았습니다.

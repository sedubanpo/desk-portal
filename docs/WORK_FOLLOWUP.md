# 업무 팔로우

`docs/work-followup.js`, `docs/work-followup.css`, `services/desk-api/src/followup/`에서 관리합니다. 메뉴는 일일 업무일지 다음에 배치됩니다.

## 원본과 조회

- 원본: Notion 중요 업무 추적 datasource `63d66cfc-8bbe-420e-9fd7-34ed4eaab301`.
- `NOTION_FOLLOWUP_TOKEN` 미설정 시 기존 `NOTION_INQUIRY_TOKEN`을 사용합니다. 토큰은 서버에만 있습니다.
- `NOTION_FOLLOWUP_SOURCE_ID`로 다른 검증용 datasource를 지정할 수 있습니다.
- 실무자(ADMIN/STAFF/DESK)와 deskPortal 접근 권한을 모두 확인합니다. 병합은 ADMIN 전용입니다.
- 노션 서버 필터·커서로 30건씩 조회하고 동일 질의는 Firestore에 30초간 캐시합니다. 전체 DB를 브라우저에 내려보내지 않습니다.
- 캐시 재조회 실패 시 마지막 조회 시각과 경고를 표시합니다. 연결 권한 오류는 캐시로 숨기지 않습니다.
- 새로고침은 캐시를 건너뜁니다. 포털 저장 완료 시 캐시 세대를 무효화합니다.
- 탭 숫자를 전체 업무 수로 오인하지 않도록 현재 페이지 건수만 표시합니다.

## 저장과 이력

- 업무 ID는 노션이 생성합니다. 원본 필드와 기존 근거는 유지합니다.
- 속성 지문을 비교해 편집 충돌을 감지하고, 포털 쓰기는 업무별 Firestore lease로 직렬화합니다.
- Notion은 조건부 원자적 PATCH를 제공하지 않으므로 외부 동시 편집에 대해 완전한 CAS를 보장하지 않습니다. 저장 직전/직후 원본을 검증해 충돌을 알려줍니다.
- 요청 번호와 `원문메시지키`의 `portal:` 표식으로 결과가 유실된 요청을 재확인합니다. 불명확한 생성 요청을 무조건 다시 POST하지 않습니다.
- 기존 근거 아래에 작성자, 시각, 변경 전후 값과 후속 메모를 추가합니다.
- 해결에는 해결 근거가 필요합니다. 재개 시 해결일만 비우고 근거는 보존합니다.
- 병합은 대표 업무 관계를 기록하며 원본을 삭제하지 않습니다. 이미 병합된 업무를 다시 대표로 지정할 수 없습니다.
- 학교·과목 연결은 관련대상에 `[학교:이름] [과목:이름]` 형식으로 보존합니다. 직접 지정한 연결에만 아이콘을 표시하며 제목에서 임의 추론하지 않습니다.

## 파일 검토

- CSV: Date/User/Message 또는 날짜/이름/내용 계열 머리글, 따옴표·여러 줄 메시지 지원.
- TXT: 카카오톡 PC 날짜 구분선 + `[발신자] [오전/오후 시각]`, 모바일 날짜·시각·발신자 형식 지원.
- UTF-8/EUC-KR 선택, 5MB 및 20,000개 메시지 제한. 새벽·자정·정오 시각을 KST로 해석합니다.
- 요청 표현을 이용한 규칙 기반 후보 분류입니다. AI가 의미를 확정하는 기능이 아니며 누락된 후보는 ‘후보만 보기’를 해제해 직접 선택합니다.
- 원문은 검토용 저장소에 보존하고 열 개씩 읽습니다. 잘못된 형식과 무시한 행 수를 알립니다.
- 유사 업무 검색을 먼저 보여주지만 자동 병합하지 않습니다. 담당자·기한·해결 여부도 자동 확정하지 않습니다.
- 새 업무 / 기존 업무에 후속 추가 / 업무 아님을 사람이 결정합니다.
- 한 메시지의 여러 업무는 ‘추가 업무로 분리’로 등록합니다. 각 슬롯은 독립적인 등록 영수증을 갖습니다.
- 방+발신자+시각+원문으로 메시지를 식별합니다. 동일 파일/메시지의 재등록은 방지하며, 이미 연결한 업무와 제외 기록을 다시 보여줍니다.
- 검토 전 입력 중인 폼 초안은 현재 화면 세션에만 유지됩니다. 완료한 등록·제외 결과와 원문은 서버에 보존됩니다.
- 기존에 다른 도구로 등록한 노션 항목은 메시지 키 방식이 다를 수 있으므로 유사 업무를 확인한 후 연결해야 합니다.

## 검증

```sh
node --test services/desk-api/test/*.test.js
PLAYWRIGHT_MODULE=/path/to/playwright CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node services/desk-api/scripts/test-followup-browser.cjs
```

브라우저 검증은 합성 데이터만 사용합니다. 목록 필터, 최소 수정 payload, 신규 입력, 대화 검토, 이스케이프, 모바일 너비, Escape 닫기를 확인합니다. 운영 자료의 저장·삭제를 테스트로 수행하지 않습니다.

API와 프론트엔드를 함께 반영해야 합니다. 기존 Cloud Run 환경변수·시크릿·서비스 계정을 유지하고 API를 먼저 반영한 뒤 GitHub Pages를 갱신합니다.
